# 自适应规则提取与通用引擎架构

> 文档版本：1.0
> 基线日期：2026-09-02
> 当前状态：架构已确定，第一批通用抽象已落地
> 适用范围：所有 PDF 类型与任意物理页数 `N`

## 1. 结论

项目应当在处理新文档的过程中持续积累证据、发现重复模式并提出可复用规则，但生产引擎不能在一次任务中无审计地自行修改规则。正确方式是“运行时动态识别与选择，运行后提取候选规则，经过跨文档回归后版本化晋升”。

这样同时解决两个问题：

- 新书籍、新版式和新内容可以产生新的规则候选，不必把当前 6 页或 381 页写成通用真理；
- 同一任务仍然可复现。任务开始后冻结规则、模型、参数和代码指纹，运行中只增加证据和异常记录，不改变已经冻结的决策逻辑。

## 2. 必须分开的五类知识

### 2.1 通用不变量

对所有输入都成立，直接进入核心引擎：

- 页数、页序和页面尺寸必须与本次输入一致；
- 正文图片、文字冲突、遗漏、重复和溢出必须被审计；
- 所有输出块都要保留来源、选择原因和回退方式；
- 恢复必须匹配完整任务指纹；
- 动态抽样不能替代全部 `N` 页自动门禁。

### 2.2 版式族规则

对一类结构相似、但源文件不同的页面成立，例如中文考试题、双栏论文、财务报表或教材目录。它们由可观察特征触发，不能由书名或固定页码触发。每条规则必须有稳定 `rule_id`、版本、适用特征、排除条件、正例、反例和质量指标。

### 2.3 源文档验收配置

只对一个精确源文件成立，例如当前书籍的 6 页样式记录、目录人工转写和已经人工核对的文字修复。配置必须绑定源 PDF SHA-256 和预检页数；未完整匹配时不得加载。

源文档配置是审计数据，不是通用规则，也不能自动传播到其他 PDF。

### 2.4 当前任务动态证据

全量普查、页面类型、版式聚类、风险特征、动态首批页、异常页、渲染差异和人工复核结果只属于当前 `task_id`。它们用于当前任务选择和后续规则分析，但不能作为另一任务的 OCR/PageModel 缓存。

### 2.5 候选规则

候选规则是从多个任务的匿名结构证据中归纳出的建议，不在产生它的任务中直接生效。它至少包含：

- 候选 `rule_id`、目标层级和建议版本；
- 触发特征与排除特征；
- 支持它的独立源哈希集合；
- 失败页、反例页与适用边界；
- 修复前后的质量指标；
- 可能影响的既有页面类型和回归集合；
- `proposed`、`evaluating`、`approved`、`rejected` 或 `superseded` 状态。

候选规则正文不得保存不必要的整页内容；人工转写和源图仍留在访问受控的源文档配置或任务证据目录中。

## 3. 引擎分层

```text
源 PDF
  → 预检与 N 页全量普查
  → 通用特征与内容探测器
  → 页面类型、版式聚类和风险描述
  → 精确源配置解析（可为空）
  → 版本化版式策略与质量策略
  → OCR / PageModel / Word 重建
  → 全量自动门禁与动态复核
  → 当前任务证据
  → 任务后候选规则提取
  → 跨文档评估、人工批准和新版本发布
```

依赖方向必须保持单向：核心数据模型和通用探测器不能反向依赖某一本书；源文档配置只能提供数据，不能在加载时执行任意代码。

## 4. 运行时动态与规则升级的边界

### 4.1 同一任务内允许动态变化

- 根据当前 `N` 页普查结果扩大动态首批页；
- 新类型、离群页和高风险页动态进入复核集合；
- 在冻结策略允许的范围内选择 OCR 重试、区域切分和设备降载；
- 追加异常、质量指标、人工结论和候选规则证据。

### 4.2 同一任务内禁止变化

- 修改页面分类或质量阈值实现；
- 把人工修复临时写回通用规则；
- 下载或替换未进入任务指纹的模型；
- 将另一任务的 OCR、PageModel 或 Word 结果并入当前任务；
- 在后半程启用一个未冻结的新规则版本。

需要修正规则时应停止当前任务，生成新规则版本并创建新任务。这样才能准确比较修改前后结果。

## 5. 候选规则晋升流程

1. `observe`：记录失败区域、页面特征、触发规则、预期与实际结果。
2. `cluster`：按结构特征聚类相似问题，不按书名或物理页码聚类。
3. `propose`：生成候选触发条件、排除条件和最小修复动作。
4. `counterexample`：主动搜索相似但不应触发的页面，防止过拟合。
5. `evaluate`：在多个独立源文件、已有正例、反例和边界页上离线重跑。
6. `approve`：人工确认适用范围和风险，将规则晋升到源配置、版式族或通用层。
7. `version`：更新规则注册表和任务指纹版本，不静默覆盖旧规则。
8. `monitor`：后续任务记录命中率、误触发率、回退率和质量变化；退化时撤回或替换。

一次源文件中的人工修复默认只能进入源文档配置。只有触发条件能用源内容之外的结构特征表达，并通过独立源文件的正例与反例验证后，才允许晋升为版式族规则；通用不变量必须能跨版式族成立。

## 6. 当前已落地的抽象

### 6.1 源文档配置注册表

`src/pdf2word_engine/document_profiles.py` 负责加载、验证和精确匹配只含数据的 JSON 配置。当前书籍的 SHA-256、381 页事实、6 页样式记录、7/21/23 额外复核页、固定页面分类、水印清理策略、目录转写与人工审校修复已移出通用重建算法，集中在：

`src/pdf2word_engine/profiles/banyuetan_xingce_1000_part2_v1.json`

配置未同时匹配 SHA-256 与页数时，分类器、目录和人工修复均不会继承这些数据。

### 6.2 动态抽样选择器

`src/pdf2word_engine/dynamic_sampling.py` 只依赖本次全量普查记录，按首末页、检测到的封面/目录、页面类型、版式聚类、章节、重建模式、未知类型、离群、高风险分和风险特征确定性选择动态首批页。它支持任意 `N`，不含当前书籍页码。

### 6.3 版本化质量阈值

`src/pdf2word_engine/quality_policies.py` 将可编辑覆盖率阈值从报告函数中移出。已接受的 6 页候选使用明确命名的历史兼容策略；未来正式任务使用未知内容默认不放行的严格全书策略。报告记录实际 `policy_id`。

### 6.4 通用版式族雏形

`src/pdf2word_engine/layout_profiles.py` 已按“中文考试题版式族”命名，而不是按当前书名命名。它仍需在后续把 OCR 内部对单一全局 profile 的直接引用改为显式策略注入。

## 7. 仍需继续抽象的边界

以下工作尚未伪装成已完成：

- 从全量缩略图与 PDF 结构生成 `PageInventoryRecord` 的通用普查器；
- 基于视觉与结构特征识别封面、目录、章节首页、表格、公式、图形和材料题，不依赖源配置页码；
- 把 OCR 中对 `CN_EXAM_QUESTION_V1` 的全局引用改为按页面选择的版式策略注入；
- 将目前仅有的中央中性灰视觉水印探测器进一步参数化，并增加由用户选择的保留/删除策略；当前探测器只会由精确匹配的源配置启用；
- 为未知 PDF 提供 OCR 驱动的通用目录重建；当前人工目录转写只对精确源配置有效；
- 建立候选规则存储、跨任务结构指标聚合、反例搜索和离线评估工具；
- 将严格全书质量策略接入尚未实现的任意页数正式入口；
- 将规则、profile、模型、参数和选择器版本全部写入严格恢复指纹。

## 8. 测试要求

- 无源配置时，固定页码不改变页面分类或抽样；
- SHA-256 或页数任一不匹配时，源配置解析结果为空；
- 配置内页码、目录页和人工修复坐标越界时加载失败；
- `N = 1`、`N < 7`、`N = 381` 和 `N > 381` 的动态选择均不越界；
- 相同普查输入与策略版本产生相同 manifest；
- 新页面类型、离群页、高风险页和风险特征不会静默漏选；
- 严格质量策略对未知内容使用非零阈值；
- 新规则只能通过新版本进入新任务，旧任务结果保持可复现。

## 9. 当前阶段

当前阶段不是运行 381 页，而是先把可扩展边界固定并补齐测试。本文件第 6 节的第一批抽象已经完成；第 7 节列出的普查器、策略注入和候选规则评估仍需按风险逐项实现。只有这些边界接入正式任务指纹后，才开始任意页数正式入口和当前 381 页大型验收。
