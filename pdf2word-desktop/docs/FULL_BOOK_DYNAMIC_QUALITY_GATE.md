# 任意页数 PDF 全书动态质量门禁实施规范

> 文档版本：1.2
> 基线日期：2026-09-02
> 当前状态：已确定，等待代码实施
> 适用范围：任意页数 PDF 的正式 source-first 任务；`N` 为预检从当前输入 PDF 读取的实际物理页数
> 当前大型验收基准：`D:\work\31.半月谈行测1000题下.pdf`（`N = 381`）
> 适用阶段：M1 转换引擎 MVP

## 1. 文档地位

本文档是任意页数正式任务的全量普查、动态抽样、分批执行、逐页门禁、全书渲染、人工复核、状态判定和恢复约束的唯一权威规范。

- `PROJECT_PLAN.md` 只保留产品目标、里程碑和总体顺序；
- `docs/SOURCE_FIRST_EDITABLE_HYBRID_REBUILD.md` 负责 OCR、PageModel 和 Word 重建规则；
- `docs/M1_QUALITY_GATES.md` 负责 M1 通用质量阈值；
- `docs/ADAPTIVE_RULE_ARCHITECTURE.md` 负责通用规则、版式族策略、源配置、任务证据和候选规则的分层与晋升；
- 本文档负责把上述规则组织为可执行的 `N` 页全书门禁。

如果其他文档中的固定页清单、抽样顺序、状态定义或恢复规则与本文档冲突，以本文档为准，并同步修正冲突文档。任何降低全书检查范围、放宽正文可编辑性或改变恢复指纹的修改，必须先更新本文档并说明原因。

## 2. 已确定的核心结论

### 2.1 6 页候选的地位

物理页 7、8、9、10、21、23 的 v2 候选已经通过自动检查、Word/LibreOffice 渲染、逐页目检和用户确认。它只证明当前样式以及已覆盖的章节首页、普通题目、分数公式、谈标签、侧栏和页码规则达到要求。

这 6 页是样式与核心算法验收记录，不是以下任何一种工件：

- 当前 PDF 全书质量通过证明；
- 正式任务固定抽样清单；
- 可供正式任务读取的 OCR 或 PageModel 缓存；
- 可替代当前源 PDF 的人工真值；
- 对表格、图形、材料题和未知版式的覆盖证明。

后续页面沿用已确认的 v2 视觉与可编辑性目标，但正式任务必须从当前源 PDF 和本次任务上下文重新产生全部页面证据。

### 2.2 不设置固定页数基线

正式任务不设置固定页数的前置或长期回归批次，不维护固定页面的 PageModel、DOCX、PNG、CER 或视觉金标，也不在动态首批页通过后重新建立另一个正式任务。

动态首批页必须由本次 `N` 页任务的全量普查结果确定，属于同一任务、同一指纹和同一检查点体系。已经在该任务内通过完整门禁的页面可以在后续阶段复用；不得跨任务复用。

### 2.3 抽样不能代替全量自动检查

动态抽样的作用是决定高成本渲染复核和人工高清检查范围。以下检查必须覆盖当前输入的全部 `N` 页：

- 源页存在性、物理页序和页面尺寸；
- OCR/PageModel 产物完整性及工件哈希；
- 正文图片硬门禁；
- 可编辑覆盖率；
- 低置信度、冲突、重复、遗漏、异常重叠和阅读顺序；
- 回退类型、来源、原因和白名单；
- 段落换行、边界与溢出预测；
- 最终 DOCX 页数、页面顺序和结构；
- 最终 Word 全书渲染后的空白、黑块、乱码、裁剪、溢出和跨页漂移检测。

任何只检查少数页面便声明全书质量通过的实现均不符合本文档。

### 2.4 页数参数化与基准配置

预检必须从当前源 PDF 读取正整数 `N = page_count`。页面循环、任务进度、检查点、页码边界、全量检查、DOCX 组装和最终页数断言全部使用该 `N`，正式引擎和通用门禁中不得把 `381`、`7`、`21`、`23` 或任一固定页码写死。

与具体书籍有关的已确认样式页、必看页和预期页数只能存放在独立的源文档验收配置中，并至少绑定源文件 SHA-256；只有配置与当前源指纹完整匹配且所有配置页码均处于 `1..N` 时才可启用。当前《半月谈行测1000题下》大型验收配置记录 `expected_page_count = 381`、样式记录页 `7、8、9、10、21、23`，并为该书额外建议复核 `7、21、23`。其他 PDF 默认不继承这些页码或页数。

## 3. 正式任务总流程

```text
创建正式任务并冻结完整指纹
  → N 页全量低成本普查
  → 页面分类、特征提取、聚类和风险排序
  → 在同一任务内生成动态首批页 manifest
  → 动态首批页完整 OCR、PageModel、Word QA 和人工复核
  → 分批处理其余页面并执行逐页硬门禁
  → 全部 N 页 PageModel 静态门禁通过
  → 组装 N 页 DOCX
  → Microsoft Word/LibreOffice 全书渲染
  → N 页全量自动渲染检查与差异计算
  → 扩充最终动态复核页集合
  → 全量缩略图巡检和动态页高清复核
  → 写入最终状态与完整质量报告
```

动态首批页通过只允许任务继续，不代表 `conversion_completed` 或 `full_book_quality_passed`。

## 4. 正式任务与完整指纹

### 4.1 任务身份

每次正式任务必须创建不可变的 `task_id`。工作区和输出目录必须按任务隔离：

```text
runtime/jobs/<task-id>/
  task-manifest.json
  state.sqlite
  inventory/
  pages/<physical-page>/
  quality/
  render/
  logs/

outputs/<task-id>/
  <source-stem>-source-first.docx
  <source-stem>-quality-report.json
  <source-stem>-dynamic-sampling-manifest.json
```

输入 PDF 不得被覆盖，临时文件不得写入输入目录，正式输出不得覆盖历史任务结果。

### 4.2 必须冻结的指纹字段

任务开始前至少冻结：

- 源 PDF 规范化绝对路径、文件大小、SHA-256、物理页数、逐页尺寸和物理页序摘要；
- 当前代码提交 ID；工作区存在代码修改时还要记录相关源文件内容哈希，不能只记录分支名；
- PageModel schema 版本；
- 匹配到的源文档 profile ID、版本与配置内容哈希，未匹配时明确记录为 `null`；
- 版式族规则、质量策略、冲突策略和规则注册表版本；
- OCR、版面、公式、表格和渲染引擎的名称与版本；
- 全部模型标识、模型文件清单和逐文件 SHA-256；
- DPI、语言、页面范围、阈值、批次大小及全部影响结果的参数；
- 字体映射和 Word 生成策略版本；
- 请求设备、实际设备、GPU 型号、运行配置和 CPU 回退策略；
- 操作系统、Python、Microsoft Word、LibreOffice 和必要时 WPS 版本；
- 动态选择算法版本和确定性种子。

指纹采用规范化排序后的 JSON 计算总 SHA-256。任务运行期间这些字段不得原地修改。

## 5. 严格同任务断点恢复

只有用户明确选择恢复原 `task_id`，并且当前环境与任务完整指纹逐项一致时，才允许恢复。

### 5.1 可复用页面条件

某一页只有同时满足以下条件才能跳过已完成阶段：

- 属于当前 `task_id`；
- 页面源图、OCR 原始证据、PageModel 和质量记录均存在；
- 每个工件的 SHA-256 与页面检查点一致；
- PageModel 已通过当前任务冻结的静态门禁；
- 页面没有 `failed`、`needs_review` 或未完成的阶段；
- 该页没有在崩溃时处于写入中状态。

页面产物必须先写入临时文件，完成校验后再原子改名并提交检查点。仅有文件存在、目录存在或数据库状态存在均不足以证明该页可复用。

### 5.2 必须拒绝恢复的情况

以下任一情况发生时必须拒绝恢复并说明差异，不提供强制忽略选项：

- 源文件、页数、页面尺寸或页面顺序变化；
- 代码、schema、模型、权重、参数或字体策略变化；
- 实际 OCR 执行配置与冻结配置不一致；
- 检查点或页面工件哈希不一致；
- 使用其他任务目录、旧输出、人工修补 PageModel 或单独拷贝的页面文件；
- 无法证明某个工件属于当前任务。

因修复代码或调整规则导致指纹变化时，必须创建新任务并重新处理，不能把旧任务页面拼接进新结果。

### 5.3 允许直接重试组装的情况

如果全部 `N` 页 PageModel 已在同一任务内通过静态门禁，仅 DOCX 组装、渲染或报告生成失败，可以复用这些已校验 PageModel 重试对应阶段，不重新 OCR。

## 6. `N` 页全量普查

全量普查在高成本 OCR 前覆盖所有物理页。它可以使用 PDF 结构、低分辨率渲染、页面缩略图和轻量特征，但结果必须来自当前源 PDF。

每页至少记录：

- 物理页码、页面尺寸、旋转、PDF 对象概况和水印标记；
- 页面类型和置信度；
- 章节归属及章节边界；
- 单栏、双栏、侧栏、材料区、题目区等版面特征；
- 文字密度、行数估计、字号分布和留白比例；
- 公式、分数、表格、图表、插图和装饰区域的数量与面积估计；
- 版式聚类 ID、聚类距离和是否属于离群页；
- 页面复杂度分数及具体风险原因；
- 是否为未知页面类型或未知内容组合。

页面分类不能直接决定整页截图。未知类型、低分类置信度和聚类离群页必须进入动态首批页或人工复核，不能静默套用普通页规则。

## 7. 动态首批页选择

### 7.1 选择原则

动态首批页没有固定数量。选择必须持续到以下覆盖矩阵没有未说明的空项：

```text
页面类型 × 版式聚类 × 章节 × 重建模式 × 风险特征
```

同一页面可同时满足多个覆盖项。选择算法必须确定性运行，相同指纹产生相同结果。

### 7.2 强制纳入

动态首批页至少包含：

- 首个物理页、末页，以及检测到的封面和全部目录页；
- 与当前源文件指纹完整匹配的验收配置所声明的额外复核页；当前大型基准才额外包含物理页 7、21、23；
- 每种页面类型和重建模式的典型页；
- 每个版式聚类中最接近中心的典型页和风险分最高的页面；
- 每章的章节首页，以及章节内出现的新页面类型；
- 所有未知类型、聚类离群和低分类置信度页；
- 表格、图表、真实图形、复杂公式、材料题、双栏和跨区阅读顺序的覆盖页；
- 文字最密、图片面积最大、公式最多和预计换行风险最高的页面。

如果高风险或未知页面较多，动态首批页可以扩大到任意数量，包括当前输入的全部 `N` 页，不能为满足人工抽样上限而排除风险页。

### 7.3 选择记录

每个入选页必须在 manifest 中记录所有选择原因、覆盖项、风险分和选择阶段。不能只保存页码列表。

动态首批页属于正式任务自身。首批页通过后，任务在相同 `task_id` 下继续处理剩余页，不重复识别首批页。

## 8. 动态首批页门禁

动态首批页必须走完整链路：

```text
当前源 PDF → 水印清理 → 正式参数渲染 → OCR/版面分析
→ PageModel → 静态门禁 → 同任务 QA DOCX
→ Word/LibreOffice 渲染 → 源页对照 → 人工确认
```

首批页必须覆盖第 9 节的通用与专项门禁。任何硬失败都将任务置为 `needs_attention`，不得进入剩余页面批次。

QA DOCX 只是当前任务的验证产物，不是最终输出，也不能成为其他任务的恢复输入。

## 9. 全量逐页门禁

### 9.1 通用硬门禁

全部 `N` 页必须逐页检查：

- 当前物理页的源证据、输出块和阅读顺序完整；
- 主 OCR、局部 OCR 和可编辑修复之间没有未解决的重复或冲突；
- 题干、选项、答案、解析、提示、分数和公式的 `body_image_blocks` 为 0；
- 图片与文字冲突为 0；
- 可编辑覆盖率达到页面类型阈值；
- 没有未解释的低置信度正文、遗漏区域或异常重叠；
- 页面编号、题号、选项和谈标签宿主关系有效；
- 段落预计高度、换行和页面边界不产生溢出；
- 所有回退块都有来源、坐标、类型、原因、等级和替代关系；
- 未知页面类型和未知内容组合未被普通规则静默吞掉；
- 页面工件、检查点和报告的哈希一致。

正文语义无法确认时，该页失败；不得以词组、单行、公式区域、单题或整页正文截图使其通过。

### 9.2 内容类型专项门禁

| 内容类型 | 必须检查的专项内容 |
| --- | --- |
| 表格 | 表格边界、行列数量、合并关系、单元格文字完整性、阅读顺序、跨页与溢出；不能可靠结构化时必须明确质量状态，不得伪装成普通段落 |
| 数学公式 | 分子分母、上下标、运算符、括号和等式完整；优先 OMML，其次可编辑线性表达；正文公式不得截图 |
| 图表与真实图形 | 图形可保留源图，但题干、图题、图例、可编辑标签和答案归属必须明确，图像不得覆盖正文 |
| 材料题 | 材料范围、题目归属、段落顺序和跨区阅读顺序正确，不得把材料与下一题错误合并 |
| 双栏与侧栏 | 主栏阅读顺序、侧栏类别、艺术页码和正文边界正确，装饰侧栏不能抢占正文 |
| 目录 | 目录文字可编辑，点引导线、页码、章节目标和内部跳转正确 |
| 章节首页 | 艺术标题和 Logo 可保真，正文继续使用可编辑段落，不得默认整页截图 |

页面出现已识别的专项内容但没有相应处理器或质量检查时，必须失败或进入人工处理，不能仅凭通用覆盖率通过。

### 9.3 硬失败与复核事件

硬失败立即停止后续批次，包括：

- 正文图片、公式图片或未允许的整页回退；
- 覆盖率失败、源内容缺失、未解决冲突或低置信度正文；
- 页面溢出、缺页、重复页、乱序或不可读取的 PageModel；
- 未知页面被无对应规则直接写入最终 Word；
- 检查点、工件哈希或任务指纹异常。

不会立即停止但必须加入最终动态复核集合的事件包括：

- 已成功完成的自动修复升级；
- 允许的 CPU 回退；
- 装饰或真实图形面积异常；
- 接近阈值的可编辑覆盖率、置信度或溢出预测；
- 源页与 Word 渲染差异超过预警阈值但未达到硬失败阈值。

复核事件可以让识别批次继续，但在复核完成前禁止 `full_book_quality_passed`。

## 10. 分批执行与停止策略

动态首批页通过后，剩余页面按确定性物理页序分批处理。默认批次大小为 24 页，可以根据显存和内存调整，但该值必须写入任务指纹。

每批必须执行：

1. 处理本批尚未完成的页面；
2. 写入并校验逐页检查点；
3. 对本批所有页面执行通用与专项静态门禁；
4. 更新任务报告、异常集合和动态抽样 manifest；
5. 原子提交批次状态后才进入下一批。

硬失败发生时立即停止新页面调度，完成当前正在写入文件的安全回滚，将任务置为 `needs_attention` 并保留此前已提交检查点。

运行时崩溃、断电或进程被强制结束时，在完整指纹一致的前提下只重做未提交或校验失败的阶段。代码或规则修复后指纹变化，必须开启新任务。

## 11. `N` 页 DOCX 组装与全书渲染

### 11.1 组装前条件

只有全部 `N` 页 PageModel 均存在、工件哈希有效且逐页静态门禁通过，才允许组装最终 DOCX。

组装必须保持源 PDF 的物理页数、页面尺寸、顺序和分页，不得因单页失败而跳页，也不得自动插入未说明的空白页。

### 11.2 全书渲染

最终 DOCX 必须至少完成：

- Microsoft Word 全书打开、保存或导出；
- LibreOffice 全书渲染用于开发期交叉检查；
- 必要时 WPS 打开和兼容性记录；
- 渲染结果物理页数必须等于预检得到的 `N`。

### 11.3 `N` 页全量自动渲染检查

对每一张最终渲染页执行：

- 空白页、近空白页、全黑页和大面积异常色块检测；
- 缺字、乱码、图片损坏、裁剪和页面边界越界检测；
- 文本密度、图片面积和主要内容区域与源页的异常差异检测；
- 页码、章节边界、物理页序和跨页漂移检查；
- 源页与 Word 渲染页的全局及区域级差异计算；
- 与该页 PageModel 的可编辑字符、图片和公式数量一致性检查。

全量自动检查产生的新异常页必须追加到最终动态复核集合，不能因为它们未在动态首批页中而忽略。

## 12. 最终动态复核与人工门禁

### 12.1 最终复核集合

最终动态复核集合是以下页面的并集：

- 动态首批页；
- 每个页面类型、版式聚类、章节和重建模式的最终代表页；
- 所有自动修复、CPU 回退、未知类型和聚类离群页；
- 所有表格、复杂公式、图表、材料题和跨区阅读顺序风险页；
- 所有接近阈值或超过渲染差异预警阈值的页面；
- 全书渲染后新增的任何异常页。

集合不设最大页数。某一风险条件命中大量页面时，应检查全部命中页或先修正规则重新运行，不能随机删减异常页。

### 12.2 人工检查范围

人工门禁至少包括：

- 浏览全部 `N` 页缩略图总览，检查系统性空白、错页、黑块、密度突变和章节漂移；
- 对最终动态复核集合逐页高清对照源 PDF；
- 在 Microsoft Word 中实际检查目录、表格、公式、谈标签和代表正文的可选择、复制和修改；
- 对 WPS 兼容性单独记录，不以 WPS 代替 Microsoft Word 最终门禁。

人工复核必须记录检查人、时间、页码、结论和未通过原因。没有人工记录时，`human_review.status` 必须为 `pending_review`，`full_book_quality_passed` 必须保持为 `false`。

manifest 是本次任务的质量证据，不是下次运行可读取的 OCR、PageModel 或 DOCX 缓存。

## 14. 状态模型

任务生命周期与质量里程碑分开记录。

### 14.1 任务生命周期

- `created`：任务和完整指纹已建立；
- `inventory_running` / `inventory_completed`：全量普查执行中/完成；
- `canary_running` / `canary_passed`：动态首批页执行中/通过；
- `running`：剩余页面分批处理中；
- `paused`：用户暂停；
- `needs_attention`：硬门禁或人工决策阻止继续；
- `cancelling` / `cancelled`：取消中/已取消；
- `failed`：不可恢复的系统失败；
- `completed`：任务执行阶段结束，不等同于质量通过。

### 14.2 质量里程碑

- `conversion_completed`：全部 `N` 页 PageModel 和最终 DOCX 已生成，不代表质量通过；
- `static_quality_passed`：全部 `N` 页逐页静态、可编辑性及专项门禁全部通过；
- `full_book_render_completed`：最终 DOCX 已成功渲染为 `N` 页并完成全量自动检查；
- `current_run_e2e_passed`：本次动态首批页、最终动态复核集合和源页—Word 完整链路通过；
- `full_book_quality_passed`：上述状态全部通过，人工复核完成，完整报告和 manifest 已冻结。

任何上游状态失败或缺失时，下游状态不得为通过。界面和报告不得把 `conversion_completed` 显示为“转换质量完成”。

## 15. 防止规则只对样本过拟合

- 正式实现必须审计按物理页码、题号或当前源哈希写死的修复规则；
- 页面特例可以作为可追踪的源约束修复存在，但不能被宣传为通用规则覆盖；
- 相似结构应使用版式、语义和源区域特征识别，不能仅使用页码命中；
- 每个通用修复必须有正例、反例、边界条件和不相关页面不受影响的测试；
- 动态首批页通过后遇到的新页面结构必须扩展规则和测试，不能静默降级；
- 代码修改会改变任务指纹，修复后的正式结果必须来自新任务，不拼接旧任务页面。
- 当前任务可以追加观察和候选规则证据，但不得在运行中改写生效规则；规则必须按照 `docs/ADAPTIVE_RULE_ARCHITECTURE.md` 离线评估、版本化并从新任务开始生效。

## 16. 实施与测试清单

### 16.1 代码实施顺序

1. 新增任意页数 `source-first` 正式入口和任务目录协议，由预检提供 `N`；
2. 实现完整指纹、工件哈希和严格恢复校验；
3. 实现 `N` 页全量普查、页面特征和确定性聚类；
4. 实现动态首批页选择器和覆盖矩阵；
5. 实现逐页通用门禁与表格、公式、图形、材料题等专项门禁；
6. 实现分批调度、停止、暂停、取消和同任务恢复；
7. 实现 `N` 页 DOCX 组装、全书渲染和全量自动检查；
8. 实现动态抽样 manifest、状态机和最终质量报告；
9. 完成 Microsoft Word、LibreOffice 与 WPS 实机验收；
10. M1 验收后接入桌面端。

### 16.2 必须具备的自动测试

- 相同指纹产生相同动态首批页；
- 新页面类型、版式聚类和风险页不会漏选；
- 所有异常页无条件进入最终复核集合；
- 源文件、代码、schema、模型、权重、参数和工件任一变化均拒绝恢复；
- 强制结束进程后只重做未提交页面；
- 同任务 DOCX 组装失败可以不重跑 OCR；
- 正文图片、遗漏、冲突、覆盖率失败和溢出会停止批次；
- 表格、公式、图形和材料题分别触发专项门禁；
- 任意 `N` 页输入中的缺页、重复页、乱序、黑页、空白页和跨页漂移能够被发现；
- 至少使用 `N = 1`、`N < 7`、中等页数、`N = 381` 和 `N > 381` 的输入验证边界，页码循环和进度计算不得越界；
- 非当前基准 PDF 不会继承 381 页断言或物理页 7、21、23 的验收配置，源哈希不匹配或配置页码越界时必须拒绝启用该配置；
- `conversion_completed` 不会被误判为 `full_book_quality_passed`。

## 17. 完成定义

本规范的代码实施只有同时满足以下条件才算完成：

- 任意页数正式入口能够创建、暂停、取消和严格恢复同一任务；
- 全量普查、动态首批页、覆盖矩阵和逐页门禁均有持久化证据；
- 全部硬失败会停止任务，不使用正文截图绕过；
- `N` 页 DOCX 成功生成且页面数、尺寸、顺序正确；
- Microsoft Word 和 LibreOffice 完成全书渲染；
- `N` 页全量自动检查完成；
- 全量缩略图巡检和动态页高清人工复核完成；
- manifest、质量报告、日志和工件哈希完整；
- `full_book_quality_passed` 的所有前置状态均真实通过；
- 自动测试、崩溃恢复测试和大型基准文件测试通过。

在这些条件满足之前，项目只能报告“正式管线实施中”“转换已完成”或“等待复核”，不得报告“全书质量通过”。当前大型基准只有在其实际 `N = 381` 的全部条件满足后，才可另外报告“381 页质量通过”。
